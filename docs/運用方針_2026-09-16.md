## 結論は4つに集約できる

### 1. 買値の利回りがすべて。増配率を当てにいくのは筋が悪い

4コホート・延べ9,308銘柄・5年先で、**リターンをきれいに説明したのは絶対利回りだけ**だった。

    絶対利回り → トータルリターン  相関 +0.252（4コホートすべて正）
    5分位で   Q1 +15%  Q2 +27%  Q3 +37%  Q4 +53%  Q5 +66%

一方で、増配率を当てる指標はいくつも見つかった。ROE 0.164、売上3年成長 0.160、
EPS3年成長 0.117。4コホートすべて同符号で、予測としては本物。
**だがどれもリターンにも減配の回避にもつながらなかった。**

そして「利回り ×（減配しない確率）」で期待値に一本化する試みは失敗した。
実現YOCとの相関は **0.628 対 生の利回り 0.629**。差がゼロ。
生の利回りが、すでにその情報を含んでいた。

> 高い利回りで買って、減配を避ける。それだけ。**式を複雑にしても良くならない。**

### 2. 減配は防げない。避けるのではなく、耐える設計にする

最良の選び方（高利回り × 減配歴なし）でも **5年で 39.5% が減配**する。
利回り上位10%を外しても 35.0%。

予兆はある。だが**1年先までしか読めない**。

| 何年以内の減配を当てるか | 配当性向のリフト |
|---|---|
| 1年以内 | **1.65** |
| 2年以内 | 1.34 |
| 3年以内 | 1.30 |

そして**ショックのときは、財務の健全さがほとんど効かない**。

    平時    兆候0個の減配率  5.8%（全体の0.74倍）
    コロナ  兆候0個の減配率 15.1%（全体の0.89倍）

選別で守れないなら、**1銘柄・1業種に頼らない**ほうが効く。

### 3. 業種は平時には効かないが、不況では効く

2026-09-15 に「業種は効かない」と棄却したのは、**平時の減配率**を測っていたから。
不況のときの落ち込みは別の話だった。

| 比べた2つの不況 | 業種ごとの落ち込みの順位相関 |
|---|---|
| リーマン ↔ コロナ | **+0.622** |
| リーマン ↔ 東日本大震災 | +0.455 |

毎回おなじ顔ぶれ（鉄鋼・非鉄金属・機械・電気機器・輸送用機器）がやられる。

**ただし1業種あたりの上限は意味がない。** ランダムに20銘柄選べば、もう平均12.7業種に
またがっている（33業種しかないので）。効くのは**不況に弱い9業種の合計**への上限。
リーマンの実績だけで選んだ9業種を25%に抑えると、コロナの落ち込みが 12.1% → 11.6%、
ゼロなら 9.5%。

**しかも避けてもリターンは落ちない**（高利回り候補の中で +52.1% → +54.3%、
減配率 58.9% → 54.8%）。守りとリターンのトレードオフが無い、珍しいケース。

### 4. いちばんの敵は、複利を止めるもの

銘柄選びでどれだけ工夫しても、次の4つより効き目が大きいものは無かった。

| 複利を止めるもの | 22年での差 |
|---|---|
| **配当を再投資しない** | **−37.6%**（使ってしまう）／ −25.5%（置いておく） |
| 税（NISAに入れられない） | **−9.2%** |
| 純粋なナンピン | −20〜30%（時期による） |
| 現金を寝かせる | −4〜8% |

同じ投入額（22年で2,610万円）でも、配当を再投資するかどうかだけで
**1.69億円 対 1.06億円**。年間配当も 475万 対 290万。

## 追加したしくみ

### 1. 配当ベースの上限を、買い付けの配分に入れた

評価額の上限だけでは、インカムの偏りは止まらない。高利回りの銘柄は評価額より
配当のほうが偏る（実測: 景気敏感業種は評価額22.2% に対して配当29.5%）。

    portfolio.max_income_weight: 0.05   1銘柄が年間配当に占めてよい上限
    cyclical.max_income_share:  0.25    不況に弱い9業種の合計

検証14で、1銘柄あたりの上限は **リターンをまったく犠牲にせず**実質の分散を
16.5 → 25.0 銘柄ぶんに改善した。ほぼ無料の改善。
実測: 入金100万円を配ると、景気敏感の配当シェアが 29.5% → 26.7% に下がる。

### 2. 不況に弱い業種への偏りを、画面に出した

📊 ポートフォリオ →「配当の強さ」。いま **配当の29.5%**（上限25%を4.5pt超過、
年間16,610円ぶん）。輸送用機器11.2% + 鉄鋼5.4% + 機械4.6% + 不動産4.4%。

### 3. NISA枠のタブを作った

移すかどうかは、たった1つの式で決まる。

    回収年数 ＝ 含み益 ÷ 年間配当

含み益が年間配当の何倍あるか、それだけ。20年持つなら回収年数が20年より短ければ得。
**含み損の銘柄は逆**で、売れば損失が確定して同じ年の利益と通算できる（ただし
同じ年に利益を確定している場合だけなので、既定では数えない）。

そして**移し替えと新規買いは同じ年240万円を奪い合う**。新規買いが優先（コストゼロ）。
余った年間枠で、枠あたりの得が大きい順に移す。株は一部だけ売れるので、
入り切らない銘柄は途中まで移して枠を使い切る。

### 4. 現金の配分を直した

```
cash_reserve  0.30 → 0.20
ladder        1.40/1.30/1.20/1.10/1.00/0.90/0.80（7段）
            → 1.55/1.45/1.35/1.20/1.10/0.90（6段）
              15%  20%  20%  20%  15%  10%
```

コストの9割は「現金の比率」ではなく**いつ出すか**で決まる。同じ30%でも、
10%下落で出せばコスト1.5%、30%下落まで待てば14.2%。

そして前の段は**下3段（1.00/0.90/0.80）に現金の40%を置いていた**。
市場PBRを組んで測ると、コロナの底でも1.05で、**12年間1.00を割っていない**。
その4割は12年間ずっと寝ていたことになる。

    前の段（現金30%）                        −8.4%  寝たまま40%
    採用した段（現金20%）                     −4.9%  寝たまま10%

PBR 0.80 は実在する水準（2009年3月、日経平均7,054円）なので消さない。
ただし17年来ていない水準に40%は置きすぎ。0.90 に10%だけ残す。

**regimes（相場の高さで入金を絞る）は据え置き。** 一度「効いていない」と書いたが、
日経PBRの過去が取れず株価の分布で代用したせいの誤りだった。市場PBRで測り直すと
regimes のコストは −0.9% で、一律8割に絞る −9.8% よりはるかに良い。

### 5. 同じ間違いを二度させない検算を足した

`scripts/audit.py` に追加したもの。

    A3.5  配分しても配当の偏りが悪化しないか
    A6    年度の切り方（作った配当明細で3通り確認）
    E6    年度の定義がアプリの中で1つになっているか
    E7    数値の列に文字列が紛れていないか
    E8    config.yaml を書き換えたら、その場で効くか

## 最後に — 見つかったバグ3つを忘れないために

検証を組み立てる途中で、アプリの中核に3つのバグが見つかった。
**どれも画面を見ているだけでは気づけない種類のもの。**

1. **年度の切り方がずれ、20.4%の銘柄で減配を誤判定していた**
   （229銘柄が誤って発掘対象から外れていた。サカタのタネは実際は減配ゼロなのに3回）
2. **有報の1株配当は株式分割が調整されていない**
   （2013〜2019に分割した1,530社の配当性向が壊れる。NTTの配当性向が873%と出ていた）
3. **yfinance が文字列 "Infinity" を返し、週次スキャンが落ちていた**
   （画面には何も出ないまま更新が止まる）
4. **config.yaml を書き換えても、再起動するまで効かなかった**
   （大人買いラインの段を直したのに、古い段が出続けた。「コードに数値を直書きしない」
   と決めている以上、設定が効かないのは黙って壊れているのと同じ）

**「数字が出ている」ことと「数字が正しい」ことは別。**
検証は、答えを出すためだけでなく、こういうものを炙り出すためにも回す価値がある。
