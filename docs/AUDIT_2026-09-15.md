# アプリ総点検の記録（2026-09-15）

ケンから「表の数字も死んでいる／数値が意味不明／左のタブが発掘以外押せない」と
指摘を受けて実施した点検と修正。

## 見つかった不具合

### 1. すべてのパーセント表示が100分の1になっていた（最重要）
Streamlit の `column_config.NumberColumn(format="%.2f%%")` は **値を100倍しない**。
0〜1 の比率をそのまま渡していたため、利回り 5.95% が **"0.06%"** と表示されていた。

該当は **13箇所・5ページ全部**：
利回り / 配当性向 / 自己利回り順位 / DPS成長 / 損益率 / 現在利回り / YOC /
業種構成比 / 目標利回り / トータルリターン / DPS成長 / 減配発生率

**対策**: `modules/format.to_pct()` を作り、表に渡す前に必ず通す。
検算スクリプトで全カラムの最小・中央・最大が想定範囲に入ることを確認
（業種構成比の合計が 100.0% になることも確認）。

### 2. 左のタブが押せなかった
原因は **アプリ側ではなく、起動のさせ方**。
Claude のセッションに紐づいたサーバーだったため、セッションが切れると
サーバーが落ちる。画面は表示されたままで通信だけ死ぬので、
「表示はされるがどこも押せない」状態になっていた。

**対策**: `起動.command` を用意。Finder でダブルクリックすれば、
Claude と無関係に自分で起動できる。

### 3. 保有銘柄の大半が判定不能だった
財務を取りに行く対象を「粗いふるいを通った銘柄」に限っていたため、
**保有114銘柄のうち57銘柄が「財務未取得」のまま**スコアが付かず、
一覧に "None" が並んでいた。

**対策**: 保有とウォッチリストは条件に関係なく必ず財務を取る。
スコアが空欄の場合は「判定」列に理由を出す。

### 4. 監視が95件の赤い箱の羅列だった
「基準を外れた」のような**状態**と、「減配した」のような**出来事**を
同じ見た目で並べていたため、行動できる情報が埋もれていた。

**対策**: 種別ごとに集計し、「いま判断が要るもの」（減配・指値到達・トラップ）を
上に個別表示、「状態として続いているもの」は表にたたんで下へ。

### 5. 資金投入に最低利回りの指定が無かった
スコア順に配分するため、**利回り1.23%の銘柄に資金が入っていた**。
インカム目的の口座としては明確な誤り。

**対策**: 最低利回りの指定を追加（既定3%）。

### 6. 発掘の表が17列で読めなかった
**対策**: 12列に整理し、採点の内訳（5層）はチェックボックスで任意表示に。
並び順の選択と、目標利回りに届く株価（指値）の列を追加。

### 7. カルテの指値表示が誤読を招いた
「指値 ¥2,766 ／ 現在値から +26.6%」だけでは、目標に届いているのか
待つべきなのか分からない。

**対策**: 「すでに目標利回りを超えている」「まだ届いていない」を文で言い切る。

### 8. 財務が取れていなかったのはレート制限だった
yfinance の IP 単位のレート制限に当たっていたため、候補1,217銘柄のうち
財務が埋まっていたのは696銘柄だけだった。制限が解けたあとに取り直したところ
**1,272/1,272 銘柄すべて取得できた**。

これにより:
- ゲート通過 **402 → 719 銘柄**
- ケンの保有 **86銘柄すべて判定可能**（基準を満たすのは 8 → 23 銘柄）

## 反省
画面のスクリーンショットを撮って「表が出ている」で確認を止めていた。
**表の中の数字を1つも検算していなかった**のが原因。
以降は、表示される数値を必ず機械で検算してから提出する。
